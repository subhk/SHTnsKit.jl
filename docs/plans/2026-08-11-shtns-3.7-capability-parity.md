# SHTns 3.7 Capability Parity Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver strict mathematical feature parity with SHTns 3.7 on CPU, CUDA, AMDGPU, MPI/CPU, MPI/CUDA, and MPI/AMDGPU while preserving every current public API.

**Architecture:** Keep one host-owned `SHTConfig` and one shared semantic layer for validation, coefficient conventions, quadrature, truncation, and layout. Dispatch the same public mathematical operations through `CPU()`/`GPU()` and array storage to concrete CPU, CUDA, AMDGPU, MPI, and MPI+GPU implementations. CUDA and AMDGPU share only backend-neutral KernelAbstractions kernels; allocation, FFTs, synchronization, and device selection stay vendor-specific.

**Tech Stack:** Julia 1.10-1.12, FFTW.jl, KernelAbstractions.jl, CUDA.jl, AMDGPU.jl, MPI.jl, PencilArrays.jl, PencilFFTs.jl, Test, JET, Aqua, GitHub Actions, and SHTns 3.7 reference fixtures.

## Scope and execution rules

- Work in `/Users/subha/Documents/GitHub/SHTnsKit.jl/.worktrees/shtns-3.7-parity` on branch `feature/shtns-3.7-capability-parity`.
- Preserve all current exports and call signatures. Existing `gpu_*`, `gpu_*_safe`, and `dist_*` functions remain compatibility wrappers.
- Match the mathematical surface of SHTns 3.7, not its C ABI, allocator/lifecycle API, build/profiling API, or exact performance-policy flags.
- Do not silently move ordinary GPU or MPI work to CPU. Only the explicitly named `gpu_*_safe` wrappers may fall back.
- Keep spatial fields and coefficients on their originating GPU. Small configuration tables may be built on the host once and cached on-device.
- Treat a capability as complete only when the public contract, independent CPU check, SHTns fixture check, and all required backend cells exist. Hardware cells remain visibly unverified until their runner passes.

**Step 3: Implement one canonical conversion rule**

function basis_scale_from_canonical(cfg, l::Int, m::Int)
    norm = cfg.norm === :orthonormal ? 1.0 :
           cfg.norm === :fourpi ? sqrt(4pi) :
           cfg.norm === :schmidt ? sqrt(4pi / (2l + 1)) :
           throw(ArgumentError("unsupported normalization $(cfg.norm)"))
    real = cfg.real_norm && m > 0 ? sqrt(2.0) : 1.0
    phase = cs_phase_factor(m, true, cfg.cs_phase)
    return norm * real * phase
end
